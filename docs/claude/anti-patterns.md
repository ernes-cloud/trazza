# Anti-patrones y bugs que ya pasaron

> Detalle movido desde `CLAUDE.md` el 2026-10-04 para que el fichero que se carga en cada sesión solo lleve el índice y las reglas críticas. Léelo antes de tocar esta zona.

## Anti-patterns / bugs to avoid
- **Función SQL nueva sin GRANT EXECUTE explícito (C1):** con `ALTER DEFAULT PRIVILEGES … REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC, anon, authenticated`, lo que creas en `public` no es invocable por el cliente hasta un `GRANT EXECUTE ON FUNCTION public.f(types) TO authenticated` con la firma exacta (o equivalente para overloads). `GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA` no cuenta para el lint. Server-only va con `-- grant-exempt: service_role` pegado encima del `CREATE` y `REVOKE ALL … FROM PUBLIC, anon, authenticated` + `GRANT … TO service_role`. Un `CREATE OR REPLACE` o un `DROP FUNCTION` + `CREATE` borra permisos: vuelve a emitir REVOKE/GRANT en la misma migración. Helpers en policies RLS, `DEFAULT` de columna o vistas necesitan `authenticated` aunque no haya `.rpc` en `src/`. Para IDs autoincrement prefiere `GENERATED BY DEFAULT AS IDENTITY` frente a `serial`/`bigserial`/`nextval` (menos sorpresas en doble apply y en permisos de secuencia). Lo vigila `tools/oss/migrationGrants.test.js`.
- **Variable declared before use in wrong block:** e.g. `let x = 0; if (condition) { fetch... }; use(x)` — x is never set. Always combine fetch + use inside the same block.
- **setTimeout for DB sync:** never use `setTimeout(() => reload(), 500)` — use `await reload()` directly.
- **Stale state in async closures:** don't read React state inside async functions that run after re-renders — use refs.
- **`exchangeRates` before calculation:** always fetch rates into a local variable BEFORE computing values that need them; set state after.
- **`t.fecha.split('-')` crash:** `transaction_date` can be undefined; always guard: `const fecha = (t.transaction_date || '').split('T')[0]; const [y='1970', m='01', d='01'] = fecha ? fecha.split('-') : [];`
- **Duplicate object keys:** `{ key: a, key: b }` — JS silently uses last value; always check when copy-pasting similar properties. **En `es.json`/`en.json` esto es especialmente traicionero**: el fichero parsea, la paridad de claves pasa, y sin embargo la traducción que editas NUNCA se ve porque otra con el mismo nombre la pisa más abajo (pasó con `goals_saved_label` en la sección `expenses`). `i18n-parity.test.js` lo detecta desde 2026-08-01 leyendo el TEXTO CRUDO y respetando el anidamiento — el mismo nombre en dos secciones distintas sí es legítimo.
- **`key={idx}` on lists:** use a stable unique id like `item.id` or `item.url`; index keys break React reconciliation on reorder/delete.
- **API calls in loops:** use `Promise.all()` not `for...await` when calls are independent.
- **Async route sin `asyncHandler`:** en Express 4, un `async (req,res)=>{}` sin wrapper no propaga rechazos al `errorHandler`; la petición puede quedar colgada hasta timeout. Regla: toda ruta/middleware async va envuelta en `asyncHandler(...)`.
- **Named-column select + columna sin migrar:** `select('col_a, col_b_nueva')` devuelve 400 COMPLETO si una columna no existe — y si además no se comprueba `error`, el fallo es invisible y "desaparecen" datos que sí existen. En tablas que crecen por migraciones (`user_preferences`) usa `select('*')` y comprueba `error` siempre. `SettingsPage` lo arrastraba (leía 8 columnas por nombre, con un fallback que al fallar dejaba al usuario sin TODAS sus preferencias avanzadas); migrado a `select('*')` el 2026-08-01. Si al añadir una preferencia nueva encuentras otro select con nombres, arréglalo en el mismo commit: es la forma en que una migración pendiente rompe una pantalla entera.
- **Dialogs con fila "añadir" pendiente:** si un diálogo acumula filas en un draft con botón "+", el botón Guardar debe INCLUIR la fila rellenada sin confirmar — descartarla en silencio pierde el dato y puede sobrescribir lo persistido con un draft vacío (bug de presupuestos 2026-07-25).
- **`<input type="number">` para importes:** el estándar HTML solo acepta PUNTO decimal, así que un usuario español que teclea `12,50` produce `value === ''` y salta el error de "importe inválido" — y cualquier `.replace(',', '.')` posterior es código muerto porque la coma nunca llega. Para dinero: `type="text" inputMode="decimal"` + parseo propio (`parseAmountInput` en `expenseService`). Con `inputMode="decimal"` el teclado español ofrece la coma, o sea que el `type=number` invita al error que luego castiga.
- **`new Date().toISOString().split('T')[0]` como "hoy":** eso es la fecha UTC, no la del usuario. En Madrid, entre 00:00 y 02:00, devuelve AYER (y encima choca con cualquier cálculo hecho con getters locales tipo `endOfMonthIso`). Usa un helper de fecha local (`localTodayIso`). Corolario: tampoco calcules `const TODAY = ...` a nivel de MÓDULO — se congela al importar y una pestaña abierta toda la noche prerrellena la fecha de ayer; resuélvelo al abrir el diálogo.
- **`select()` sin paginar sobre una tabla que crece:** PostgREST corta en el `max-rows` del proyecto (1000 por defecto en Supabase) y devuelve la página truncada **sin error** — el fallo es invisible y los totales empiezan a mentir. Pagina con `.range()` (+ un `.order()` de desempate estable para que las páginas no se solapen).
- **`upsert(..., { onConflict })` contra un UNIQUE PARCIAL:** un índice único con `WHERE` no es árbitro válido de `ON CONFLICT` salvo que la sentencia repita el predicado, así que el upsert falla. Para tolerar duplicados en un lote: intenta el insert y, ante un 23505, reintenta fila a fila ignorando solo los que ya existen (un insert en lote es UNA sentencia: un duplicado aborta el lote ENTERO y se pierden en silencio las filas nuevas).
- **Escribir en BD ANTES de pintar el dato en pantalla:** en `refreshPrices` el write-back de precios iba delante del `_setPositions`, así que un fallo en el bucle de escritura (una RPC ausente, un error de red) abortaba la función entera y la pantalla se quedaba con los precios guardados **sin avisar** mientras el Dashboard mostraba los vivos. Medido en modo demo: `supabase.rpc is not a function` → "Valor en Mercado" clavado en 191.295 € frente a 213.983 € del Dashboard. Regla: primero el estado de la UI, después la persistencia fire-and-forget, y ésta envuelta para que no pueda tumbar lo anterior.
- **Tragarse el error de la carga de BROKERS deja el Dashboard en CEROS, y eso se lee como "he perdido mis datos"** (2026-09-11, reportado por el owner: *"solo me carga el widget de Favoritos"*). `loadBrokers` hacía `catch { console.error }`: ante un tropiezo de red, `brokersRef.current` se quedaba vacío, `loadDashboardData` salía por su guarda de "0 brokers" y la pantalla pintaba **0 pos. · 0 € · sin gráfico** sin un solo aviso — idéntico a una cuenta nueva. Y no se recuperaba sola, porque el efecto de carga sólo dependía de `[initReady, currency, selectedBrokerId]`: aunque la lista llegase después, nadie volvía a cargar. Tres reglas que salen de aquí: (1) un fallo que vacía la pantalla se PROPAGA y se avisa, nunca se registra y se sigue; (2) el gate `initReady` se abre en un `finally` — si no, un fallo en el init congela la pantalla en su estado inicial para siempre; (3) si una carga lee un `ref` que se rellena aparte, ese conteo va en las deps del efecto (`brokers.length`), que es lo que permite recuperarse solo cuando el dato llega tarde. Los `select()` de posiciones/transacciones del Dashboard comprueban su `error` desde el mismo día.
- **Optimistic update sin rollback:** si pintas el cambio antes de persistir y el write falla, hay que REVERTIR el estado además de avisar — si no, queda en pantalla un dato que no existe en BD y desaparece al recargar (pasó con las categorías personalizadas).
- **Hardcoded metric label strings:** labels from `getEnrichedData` are uppercase with spaces — `'52W HIGH'` not `'High 52W'`.
- **Commission currency mixing in cost basis:** commissions from DeGiro/IBKR are always in EUR even for USD/GBP stocks. Never add `comisiones` to a `totalCost` that's in native currency — it inflates the average price. Track commissions separately in EUR.
- **Never name a `.map()` row variable `t` in components using `useTranslation`:** the row shadows the i18n `t()` function; any `t('key')` call inside the map then invokes the row object → `TypeError` that only fires when that row type actually renders (crashed the brokers screen the first time DB sells reached RealizedPnLTable). Use `row`/`item`.
- **`const` scoped inside if/else block:** a `const` declared inside `} else if (...) {` is invisible to sibling blocks. If a variable is needed in both BUY and SELL branches, declare it before the `if` or duplicate the declaration in each branch.
- **Monkey-patch de `console` a nivel de módulo en `vite.config.js`:** la plantilla de  traía `console.warn = () => { }`. La config se carga DENTRO del proceso que la usa (`vite build`, y el `preview()` de `tools/prerender.mjs`), así que dejaba mudo TODO `console.warn` de ese proceso: los avisos de Vite y Rollup (su logger escribe con `console.warn`; el stderr del build medía 0 bytes), el AVISO del prerender sobre el blog sin Supabase y el `errorHandler` de Sentry. Se diagnosticó mal una vez («stderr no llega al `tee`») y se tapó pasando los avisos a stdout (6083bdaa). Quitado el 2026-10-18; lo vigila `tools/viteConfig.test.js`. Hoy `vite.config.js` NO tiene `customLogger` (se quitó en d5414fd6 porque filtraba en bloque los errores de PostCSS). Si algún aviso concreto de Vite molesta, se añade un `customLogger` que filtre ESE mensaje exacto y deje pasar todo lo demás, nunca en bloque (ni por tipo de error ni por prefijo).
- **`dark:` en un `@apply` dentro de un pseudo-elemento** (`&::-webkit-scrollbar-thumb`, `&::placeholder`…): con `@custom-variant dark (&:is(.dark *))` sale `::pseudo:is(.dark *)`, que el optimizador de Tailwind (lightningcss, activo en `vite build` por NODE_ENV=production; no es esbuild) deja en un `:is()` vacío, esbuild avisa al minificar y el color oscuro no se aplica. El oscuro va en un bloque `.dark &::…` aparte. Lo vigila `tools/indexCss.test.js` de dos formas: (1) **compila `src/index.css`** con `@tailwindcss/postcss` (`optimize: true`) y lo minifica con esbuild como Vite 4.5, y exige 0 `:is()` vacíos, 0 pseudo-elementos (`::x` o `:before`/`:after`/`:first-line`/`:first-letter`) seguidos de `:is(` y 0 avisos del minificado — eso cubre cualquier forma de llegar ahí, pero solo en reglas que Tailwind emite (una `@utility` que no use ningún fichero no sale); (2) en la fuente, sin comentarios ni cadenas, busca `@apply … dark:` (también `hover:dark:`) o `@variant dark` dentro de un bloque cuyo selector, o el de CUALQUIER bloque que lo contenga, lleva un pseudo-elemento. Además `npm run build:deploy` falla si la salida del build trae un `:is()` vacío.
